# flutter_ui_lints Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a standalone `custom_lint` Dart package, `flutter_ui_lints`, with six `DartLintRule`s that enforce design-system discipline (no hardcoded colors/font sizes/font families/spacing/padding, no inline widget composition in pages) and surface directly in `flutter analyze`/`dart analyze`.

**Architecture:** One `PluginBase` (`lib/flutter_ui_lints.dart`) registers six rule classes under `lib/src/rules/`, each a `DartLintRule` matching nodes via `context.registry.add*` callbacks and reporting via `ErrorReporter`. Configurable rules read their options out of `CustomLintConfigs` once, at `getLintRules(configs)` time, via a small shared reader in `lib/src/rule_config.dart`; a second shared file, `lib/src/ast_helpers.dart`, holds the one piece of AST logic two rules share (recognizing `Type.member` / `Type.member * <literal>` token expressions). Tests use `DartLintRule.testAnalyzeAndRun(File)` (a `@visibleForTesting` method custom_lint_core ships specifically for this — no subprocess, no separate test package needed) against small fixture `.dart` files under `test/fixtures/` that import a local `stubs.dart` defining fake `Color`/`SizedBox`/`EdgeInsets`/etc. classes, so fixtures resolve as plain Dart with no Flutter SDK dependency.

**Tech Stack:** Dart (pure, no Flutter SDK dependency), `custom_lint_builder` 0.8.1, `analyzer` (`>=8.0.0 <10.0.0`, matching `custom_lint_builder`'s own floor — do not pin `^9.0.0` the way `cubit_ui_flow_lints` does, since that range doesn't overlap `custom_lint_builder`'s `^8.0.0` requirement and will fail to resolve), `package:test`.

**Spec:** `docs/2026-09-07-design.md` (this package's own docs directory) — the plan below implements every rule and config default exactly as described there. Read it first; this plan assumes it.

## Global Constraints

- Package lives at `my-libs/flutter_ui_lints`, its own git repo (same shape as `my-libs/flutter_cubit_ui_flow/cubit_ui_flow_lints`), not nested inside pocketcoder-pro.

- Every rule name, default config key, and default value must match `docs/2026-09-07-design.md` exactly — that document is the source of truth for behavior; if an implementation detail below conflicts with it, the design doc wins and the plan step is wrong.

```dart
import 'package:analyzer/dart/ast/ast.dart';

/// True if [expr] is `Type.member`, optionally scaled by a literal numeric
/// multiplier (`Type.member * 2` or `2 * Type.member`), for a `Type` whose
/// name is in [allowedTypes].
bool isTokenExpression(Expression expr, List<String> allowedTypes) {
  var target = expr;
  if (target is BinaryExpression && target.operator.lexeme == '*') {
    final left = target.leftOperand;
    final right = target.rightOperand;
    if (right is IntegerLiteral || right is DoubleLiteral) {
      target = left;
    } else if (left is IntegerLiteral || left is DoubleLiteral) {
      target = right;
    } else {
      return false;
    }
  }
  if (target is PrefixedIdentifier) {
    return allowedTypes.contains(target.prefix.name);
  }
  return false;
}

/// The lexeme of the nearest enclosing class declaration, or null if
/// [node] has none (e.g. a top-level function).
String? enclosingClassName(AstNode node) {
  return node.thisOrAncestorOfType<ClassDeclaration>()?.name.lexeme;
}
```

    });

    test('accepts a token member scaled by a literal multiplier', () {

- [ ] **Step 2: Write `test/rule_test_harness.dart`**

**Correction found while implementing Task 4** (recorded here so this
plan matches what actually ships): the pinned `analyzer` 8.4.0 has
already renamed `AnalysisError` to `Diagnostic` (`AnalysisError` is a
deprecated typedef alias, still usable but with no `.lineNumber`
getter — only `.offset`, a character offset). Line-number assertions in
every rule's test therefore need a small helper that maps an offset back
to a line number using the fixture's own source, rather than a
`.lineNumber` property that doesn't exist. `ErrorReporter` is
likewise deprecated in favor of `DiagnosticReporter` but is still what
`DartLintRule.run()`'s own signature requires — importing and using it
is correct despite the deprecation notice `dart analyze` will show; do
not "fix" that by switching to `DiagnosticReporter`, since the base
class's abstract method dictates the parameter type.

```dart
import 'dart:io';

import 'package:analyzer/error/error.dart';
import 'package:analyzer/source/line_info.dart';
import 'package:custom_lint_builder/custom_lint_builder.dart';
import 'package:path/path.dart' as path;

Future<List<AnalysisError>> lintFixture(
  DartLintRule rule,
  String fixtureFileName,
) {
  return rule.testAnalyzeAndRun(File(_fixturePath(fixtureFileName)));
}

/// 1-indexed line number of [error], read against the fixture's own source
/// -- `AnalysisError` (an alias for `Diagnostic` in this analyzer version)
/// exposes only a character [Diagnostic.offset], not a line number.
int lineNumberOf(AnalysisError error, String fixtureFileName) {
  final content = File(_fixturePath(fixtureFileName)).readAsStringSync();
  return LineInfo.fromContent(content).getLocation(error.offset).lineNumber;
}

String _fixturePath(String fixtureFileName) => path.join(
      Directory.current.path,
      'test',
      'fixtures',
      fixtureFileName,
    );
```

Every rule file below that reports via `ErrorReporter` must import it
explicitly: `import 'package:analyzer/error/listener.dart' show
ErrorReporter;` — it is not re-exported by `custom_lint_builder`. Every
rule *test* below that asserts on line numbers must call
`lineNumberOf(error, '<fixture file name>')` instead of `error.lineNumber`.
The plan's remaining code blocks (Tasks 4-9) have already been corrected
to reflect both of these; if you're implementing from an older copy of
this plan, apply both fixes by hand.

- [ ] **Step 4: Write the rule**

```dart
import 'package:analyzer/error/listener.dart' show ErrorReporter;
import 'package:custom_lint_builder/custom_lint_builder.dart';

class NoHardcodedColors extends DartLintRule {
  NoHardcodedColors({required this.bannedTypes}) : super(code: _code);

  final List<String> bannedTypes;

  static const _code = LintCode(
    name: 'no_hardcoded_colors',
    problemMessage:
        'Colour must come from a role (TextRole, SectionState, ActionKind) '
        'or context.colorScheme, never a literal Color or a palette '
        'constant.',
  );

  @override
  void run(
    CustomLintResolver resolver,
    ErrorReporter reporter,
    CustomLintContext context,
  ) {
    context.registry.addInstanceCreationExpression((node) {
      if (node.constructorName.type.name2.lexeme == 'Color') {
        reporter.atNode(node, _code);
      }
    });
    context.registry.addPrefixedIdentifier((node) {
      if (bannedTypes.contains(node.prefix.name)) {
        reporter.atNode(node, _code);
      }
    });
  }
}
```

Note: no explicit import of `package:analyzer/dart/ast/ast.dart` is needed
here -- the `addInstanceCreationExpression`/`addPrefixedIdentifier`
callback parameter types are inferred from `custom_lint_builder`'s own
registry API, so importing `ast.dart` without otherwise naming a type
from it triggers an `unused_import` warning. Only import it in a rule
file that names an AST type explicitly (several of the rules below do).

import 'package:analyzer/dart/ast/ast.dart';
import 'package:analyzer/dart/ast/visitor.dart';
import 'package:analyzer/error/listener.dart' show ErrorReporter;
import 'package:custom_lint_builder/custom_lint_builder.dart';

class NoInlineWidgetCompositionInPages extends DartLintRule {
  NoInlineWidgetCompositionInPages({
    required this.pageSuffix,
    required this.widgetDirNames,
    required this.bannedWidgetNames,
  }) : super(code: _code);

  final String pageSuffix;
  final List<String> widgetDirNames;
  final List<String> bannedWidgetNames;

  static const _code = LintCode(
    name: 'no_inline_widget_composition_in_pages',
    problemMessage:
        'Pages must compose already-built reusable widgets, not construct '
        'layout widgets inline.',
  );

  @override
  void run(
    CustomLintResolver resolver,
    ErrorReporter reporter,
    CustomLintContext context,
  ) {
    final segments = resolver.path.split(RegExp(r'[\\/]'));
    if (segments.any(widgetDirNames.contains)) return;

    context.registry.addClassDeclaration((classNode) {
      if (!classNode.name.lexeme.endsWith(pageSuffix)) return;

      for (final member in classNode.members) {
        if (member is MethodDeclaration && member.name.lexeme == 'build') {
          member.body.accept(
            _BannedWidgetVisitor(reporter, _code, bannedWidgetNames),
          );
        }
      }
    });
  }
}

class _BannedWidgetVisitor extends RecursiveAstVisitor<void> {
  _BannedWidgetVisitor(this.reporter, this.code, this.bannedWidgetNames);

  final ErrorReporter reporter;
  final LintCode code;
  final List<String> bannedWidgetNames;

  @override
  void visitInstanceCreationExpression(InstanceCreationExpression node) {
    if (bannedWidgetNames.contains(node.constructorName.type.name2.lexeme)) {
      reporter.atNode(node, code);
    }
    super.visitInstanceCreationExpression(node);
  }
}
